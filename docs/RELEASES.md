## 后续更新约定

用户偏好：**每次更新都应有明确可见的 UI 变化，让人能感受到更新已经发生。**

发布授权：每轮修改并验证完成后，自动提交并推送 GitHub；用户已配置 Cloudflare 自动关联。推送后核对公网版本，不把推送完成等同于部署成功。

1. 在 `app/release.js` 更新唯一的 id、version、date、title 和实际 changes；该文件同时决定界面版本与离线缓存版本。
2. 为本次改进提供有实际用途的可见变化，例如学习入口、反馈、统计或页面排版；保留首页版本卡，说明具体变化。
3. 检查桌面和手机，保存预览，确认页面显示的是本次版本。
4. 运行相关检查和 `node tools/smoke_studio.cjs`；该浏览器检查需要 `.dev` 下的 Playwright 和 Chromium，使用隔离的测试记录。
5. `python tools/build_dist.py` 后运行 `python tools/check_deploy.py`。构建目录是可再生成的 `dist/`。
6. 发布后检查现有安装的更新提示、切换后的版本号，以及断网重载。不应把本地完成等同于公网已更新。

V46 已通过本地桌面、手机、保存失败恢复和离线版本升级检查；公网发布状态应单独确认。
